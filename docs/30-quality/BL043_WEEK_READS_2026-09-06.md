# BL-043e.4 — Bounded Week Training Reads

- Date: 2026-09-06
- Scope: weekly calendar training reads; no schema, migration, dependency or
  authorization-policy change. Existing matches retain their shared source.
- Authority: approved BL-043 next step within ADR-0007/0014/0022/0023.
- Verdict: Pass for the week read slice; attendance cutover remains open.

## Delivery

The existing training page contract accepts optional paired ISO `from`/`until`
instants with an eight-day maximum elapsed interval. The half-open period
intersects, rather than overrides, current group/club and exact season filters.
Counter and phase queries retain those same filters and existing PLAYER-only
self-attendance. Requests without periods are unchanged. No calendar request
contains nested drills, boards or attendance arrays.

Week consumes seven independent 25-record day pages, never `workspace.plans`.
Local midnight and next local midnight are converted to UTC instants using
calendar arithmetic; short/long DST days are representable. Each day displays
full plan/duration totals and independent previous/next controls. Pages replace,
not append. Loading/error/retry cannot be mistaken for no planned activity;
failed or empty continuation retains previous navigation. Matches remain visible
when a day's training request fails. Week/club/season/team/group changes reset
and discard late old responses. Week navigation preserves existing URL scope
parameters, and clearing the date input does not create an invalid date.

Undated drafts have no calendar day; an explicit link keeps them accessible in
the training catalog without placing them on an invented date. Existing shadcn
cards, navy/blue/amber identity and horizontally scrollable seven-day board remain.

## Remaining work and trade-offs

Attendance still needs the shared full plan fetch. Do not remove it or replace
it with a first page until attendance and mutation-refresh regressions are ready.
Seven page requests mean extra per-day authorization/aggregate work, up to 175
minimal plan items per loaded week; full summaries are live, not a cross-request
snapshot. This slice bounds calendar payloads but does not claim complete
workspace performance optimization. Pilot volume/query budgets, owner/SLO (TBD),
other business lists, BL-044/045 and M4 remain open.

Next: bounded attendance reads with full player totals, followed by removal of
the shared full plan read only after all consumers and refresh paths are verified.
Rollback frontend day reads to the prior full-array week; optional API period
support can remain. No data rollback is needed. Preserve cumulative worktree edits.
